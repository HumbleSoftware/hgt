## Context
We have a project where "tickets" / work-items flow in as patches to a spec. The diff + PR get picked up as a new implementation work item. Humans own the spec. We need a quick way for Humans to get a new "work" session to implement those spec changes.

## Scope

- `hgt work <branch-name>` - starts a new working session (claude + terminal + branch + worktree) from new or existing branch
- Claude is at-the-ready but doesn't start work

## Non-goals
- Fetching from or pushing to Github issues/PRs

## Acceptance criteria
- Session starts as a work-item would
- Claude does nothing


## Getting started

1. Read this file and CLAUDE.md before starting.
2. Implement the slice; commit early and often — every commit is a recovery checkpoint.
3. Open a PR for human review. Do not merge (green is necessary, not sufficient).
